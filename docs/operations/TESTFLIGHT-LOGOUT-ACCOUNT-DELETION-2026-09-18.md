# TestFlight logout and account deletion incident (2026-09-18)

The reported TestFlight symptom is that tapping logout leaves the screen unresponsive. The latest iOS TestFlight candidate was build 21, source commit `8aad90dcc48f75311d4572ab7e05aecde727565f`, created before the account-deletion server rollout and client cleanup changes. The local simulator uses the QA wrapper and current working-tree code; TestFlight build 21 uses the EAS Production profile and the earlier client code. The supplied test email currently has no Auth user or profile row in either the QA or Production Supabase project. This establishes that the account cannot be used for a new sign-in test; the read-only check does not prove whether it was previously deleted or never existed there.

In build 21, logout awaited push-token unregistration before local data preparation, Supabase sign-out, and auth navigation. A real iPhone may have a push token and run the network RPC; a simulator often skips that path. Any rejected or indefinitely pending token operation could keep the logout confirmation in its busy state. `prepareForLogout()` could also await remote Growth Book sync. Account deletion could succeed server-side but then report failure or hang during `clearAllUserData()`, which also attempted a network Auth sign-out, before the UI completed local logout. These are code-path findings; no device trace was available to identify the particular stalled request.

The client fix runs push unregistration and pre-logout persistence concurrently with three-second deadlines, then signs out this device. A timed-out preparation receives an abort signal and cannot later reset the in-memory state of a newly signed-in account. Supabase local sign-out has a four-second deadline and a direct local-session removal fallback. BabyLog data cleanup no longer initiates Auth sign-out, so account deletion can clean local data and route out after server success. An unauthorized deletion response closes the stale deletion dialog and logs out locally. The existing server deletion fix remains unchanged.

Validation in the working tree: TypeScript, B0.4c notification security smoke, timeout behavior smoke, and `git diff --check` passed. The isolated release snapshot was built from TestFlight build 21's commit, with only the logout/deletion files, account-deletion policy/error strings, and build number 22 changed. Its TypeScript, build-version guard, and build-environment guard passed. EAS Production environment guard confirmed the intended Production Supabase project without printing credentials. The first build 22 (`c9862fed-ed04-4a2e-8328-d59fb05b152a`) was canceled before submission to add the late-preparation abort guard. The replacement build 22 EAS ID is `b93d8d60-45ca-4097-96a5-55675803dc0f`.

Build 22 `b93d8d60-45ca-4097-96a5-55675803dc0f` finished successfully. EAS submission `34fe7542-a6bd-4cbb-99e4-4f09d1ed84df` finished successfully. App Store Connect lists build 22 as `VALID` and `IN_BETA_TESTING` for internal testers; its external state is `READY_FOR_BETA_SUBMISSION`. Device-level validation must confirm the logout button returns to Auth, the app remains signed out after restart, and a separate disposable account can complete deletion. Do not use the supplied test email as the deletion canary because no corresponding Auth user exists in the checked projects.

## Follow-up: logout works, deletion still fails

The user confirmed logout now works, but supplied a second deletion error screenshot. Production logs identify a separate server failure: `db_prepare`, HTTP 503, PostgreSQL `23503`, constraint `care_reminder_state_baby_id_fkey`. Deleting the last admin's baby cascaded into feeding/sleep logs, whose DELETE trigger attempted to recreate reminder state after the parent baby was gone. Earlier account-deletion fixtures used memo logs only and missed this path.

On 2026-09-18 at approximately 13:36 UTC, migration `202609180001_account_deletion_reminder_cascade.sql` was applied to Production after QA reproduction and full account-deletion/reminder regressions. The single-function fix skips reminder synchronization when its parent baby no longer exists. Deployment verification confirmed unchanged authorization, foreign keys, and account-deletion policy. No additional TestFlight build is required. See [the detailed incident report](ACCOUNT-DELETION-REMINDER-FAILURE-2026-09-18.md) for the exact SQL stack, tests, and rollback/retry findings. A successful retry on the user's device has not yet been observed.
