# Darin Community UI/UX 재설계안

작성일: 2026-09-07 · 상태: 설계 초안, 피드 중심 인터랙션 수정 반영 · 산출물: 이 Markdown 문서만

## 1. 설계 범위와 방향

**가족과 연결된 친구가 아기의 순간을 함께 보는, iOS·Android용 프리미엄 베이비북으로 설계한다.** 사진, 아기 이름, 작성자, 공개 범위를 빠르게 읽게 하고, 함께한 사람과 짧은 이야기를 차분하게 배치한다. **메인은 피드가 주인이다. 한마디는 피드 위의 시트에서 나누고, 전체 화면은 추억 수정이나 사진 확대·여러 장 감상에만 사용한다.**

- 디자인 차별화 5/10: 기존 Darin의 크림·브라운·코랄을 사용하고 사진과 여백으로 개성을 만든다.
- 모션 강도 2/10: 누름 피드백과 화면·시트 전환 중심으로 구성한다.
- 정보 밀도 4/10: 사진의 존재감을 확보하면서 가족 구성원도 읽기 편한 크기를 사용한다.
- 이번 작업은 분석과 설계만 수행한다. 앱 코드, Figma 원본, 의존성, 설정을 변경하지 않는다.
- 후속 구현도 UI/UX와 작은 표현용 컴포넌트에 한정한다. 백엔드 스키마, API 계약, 데이터 모델, 인증, 권한 판정, 저장·업로드·동기화 방식은 그대로 유지한다.

여기서 Community는 새 화면 이름이 아니라 현재 `Memories` 영역을 가리킨다. 사용자에게 보이는 이름은 **우리 순간**, 친구 전용 진입에서는 **친구의 순간**을 제안한다. 공개 커뮤니티, 인기 게시물, 팔로워 지표를 도입하지 않는다.

## 2. Figma MCP 확인 결과

[사용자가 지정한 참조 프레임](https://www.figma.com/design/HMRf2aSnFecWGYuGytyQY2/Instagram-UI-Screens--Community-?node-id=0-2938)

- 파일 키: `HMRf2aSnFecWGYuGytyQY2`
- 노드: `0:2938`
- 실제 프레임 이름: **Instagram Profile Menu**
- 프레임 크기: **375 × 812**
- 확인 방법: Figma MCP `get_design_context`의 스크린샷·스타일 정보와 `get_metadata`의 노드 구조를 대조했다.

**이 프레임은 홈 피드가 아니라 오른쪽 메뉴가 열린 프로필 화면이다.** 프로필이 왼쪽으로 251px 이동해 오른쪽 124px만 보이고, 오른쪽 251px를 메뉴가 차지한다. 프로필의 가려진 정보는 MCP 레이어 데이터로 확인했다. 이를 전부 화면에 보이는 요소라고 해석하지 않는다.

따라서 다음을 구분한다.

- **확인값:** 아래 Figma 수치는 지정 노드의 레이어·스타일에 근거한다. 단위는 Figma px다.
- **설계 판단:** 가벼운 구분선, 정렬, 원형 이미지, 사진 중심 구조에서 가져온 원칙이다.
- **Darin 제안:** 세로 피드의 게시물 헤더, 사진 아래 반응 행, 태그 배치는 새 설계다. 참조에서 측정한 값이 아니다. 피드 유지·두 번 탭 좋아요·한마디 시트 동작은 사용자의 후속 지시를 반영했다. 지정 Figma 프레임에 댓글 시트가 없고 이번 메시지에도 새 스크린샷이 첨부되지 않았으므로 시트 수치는 제안값이다.

다른 Instagram 홈 피드 프레임을 임의로 참조 대상으로 바꾸지 않았으며, 정적 프레임으로 확인할 수 없는 탭 동작·스크롤·애니메이션은 관찰 사실로 주장하지 않는다.

우선 개선할 문제:

1. **공개 범위의 정확성:** `tagged_family`, `selected_people`가 현재 표현 함수에서 모두 ‘가족 공개’로 보인다. 기존 값을 유지하면서 각각 ‘태그된 가족’, ‘선택한 사람’으로 구별한다.
2. **아기·작성자 식별:** 사진 전에 어떤 아기의 순간이며 누가 작성했는지 보여준다. 친구 아기 사진을 작성자 얼굴의 대체 이미지로 사용하지 않는다.
3. **과도한 테두리와 작은 글자:** 색 외곽선·중첩 배지를 줄이고 사진, 본문, 공개 범위의 가독성을 높인다.
4. **버튼의 명확성:** 사진 확대, 한마디, 좋아요, 저장을 독립된 터치 영역으로 만든다. 카드 전체 버튼 안에 다른 버튼이 중첩되는 패턴을 줄인다.

## 4. 새 화면 구조

### 4.1 가족 측 ‘우리 순간’

상단 헤더는 고정하고, 가족 관리·대상 선택·보기와 게시물은 하나의 세로 목록으로 스크롤한다. 여러 줄의 상단 필터를 모두 고정해 사진 영역을 줄이지 않는다.

```text
┌──────────────────────────────────┐
│ 시스템 상태바 / 실제 safe area    │
│ 우리 순간           알림  +  설정 │
│ 가족과 나누는 아기의 하루         │
├──────────────────────────────────┤
│ 가족 구성원 N명 · 함께 보기     > │
│                                  │
│ (전체) (가족 순간) (아기) (아기) → │
│ 모든 순간                 보기 ▾ │
│                                  │
│ ○  {아기 이름}의 순간             │
│    {관계 이름} · {상대 시간}       │
│    [공개 범위 아이콘] 가족 공개    │
│ ┌──────────────────────────────┐ │
│ │                   사진 N장 >│ │
│ │          실제 커버 사진       │ │
│ │                              │ │
│ └──────────────────────────────┘ │
│ ♡ 좋아요 N   ◯ 한마디 N     저장 │
│ {실제 게시물의 짧은 이야기…}      │
│ 더 보기                          │
│ 함께한 사람 · {이름} · {이름}     │
│ ──────────────────────────────── │
│ 다음 순간                        │
├──────────────────────────────────┤
│ 기록   일기   음성   한눈에  우리 순간│
│ 실제 하단 safe area              │
└──────────────────────────────────┘
```

이 도식은 영역 순서이며 픽셀 시안이 아니다. 중괄호와 N은 실제 필드 자리다. 목업용 가족 이름, 좋아요 수, 활동 상태를 제품 데이터처럼 생성하지 않는다.

### 4.2 헤더와 관계 영역

- 좌우 패딩 16. 제목 24/30, 굵기 700. 설명 14/20, `colors.muted`.
- 알림·작성·설정은 각 48×48 터치 영역, 아이콘 22–24. 화면이 좁거나 글자가 커지면 설명을 다음 행으로 보내고 헤더 높이를 늘린다.
- 작성 버튼은 현재 `canCreate` 조건을 그대로 따른다. ‘+’ 접근성 이름은 ‘추억 올리기’. 고정 헤더의 버튼으로 스크롤 후에도 작성 가능하게 한다.
- 가족 관리 행은 현행 `onOpenFamily` 목적지로 연결한다. 초대·멤버 관리 권한 판정은 해당 기존 화면에 맡긴다.
- 구성원 수는 현재 코드의 집계 기준을 유지한다. 새 ‘읽음’, ‘접속 중’, ‘최근 본 가족’ 지표를 만들지 않는다.
- 초대된 가족이 없는 경우 ‘가족과 함께 보세요’와 현행 가족 공유 화면 진입을 제공한다. 이 안내가 작성 자체를 막지 않는다.

### 4.3 아기 대상 선택과 보기

- 기존 `babyFilter` 값 `all`, `family`, 아기 ID를 그대로 시각화한다.
- 각 항목은 폭 72 이상, 시각 이미지 48, 라벨 12/18, 이미지와 라벨 간 6. 선택 행은 기본 약 84h이며 큰 글자에서는 자동으로 커진다.
- ‘전체’는 중립 아이콘, ‘가족 순간’은 가족 아이콘. 아기 사진은 해당 아기의 실제 이미지가 이미 있을 때만 사용하고, 없으면 기존 baby 아이콘을 쓴다.
- 선택 상태는 코랄 원선과 라벨 굵기, 접근성 선택 상태로 표시한다. 무지개 스토리 링, 미확인 표시, 소멸 타이머는 사용하지 않는다.
- 아기가 한 명이면 중복 아기 선택기를 펼쳐 놓지 않고 ‘전체 / 가족 순간’을 간결하게 표시한다. 다중 아기일 때 가로 스크롤을 사용한다.
- 대상 선택은 피드 보기만 바꾼다. 앱 전체의 활성 아기와 새 게시물 작성 대상을 자동 변경하지 않는다.
- 보기 버튼은 기존 `MemoryViewFilterSheet`로 연결한다. 전체·가족 공개·친구 공개·나만 보기·태그됨·저장됨을 유지한다.
- ‘친구 공개’ 필터는 **내가 접근하는 현재 피드 중 친구 공개인 글**이다. 새 친구 피드를 합치거나 ‘친구들의 글’로 뜻을 바꾸지 않는다.
- 기존 tagged 필터는 `tagged_family` 또는 내 ID 태그 조건이다. 이번에는 필터 로직을 바꾸지 않고, ‘태그 관련 순간’처럼 실제 결과를 포괄하는 설명을 사용한다.
- 필터 결과가 비면 선택한 대상·보기 조건을 보여주고 ‘필터 초기화’를 제공한다. 현재 페이지 단위 로딩 범위를 전체 데이터 검색으로 표현하지 않는다.

### 4.4 게시물 헤더

- 좌우 16, 아래 사진까지 12. 작성자 아바타 40×40, 텍스트와 간격 10.
- 1행은 `{아기 이름}의 순간` 또는 기존 `isFamilyMoment`에 대응하는 ‘가족 순간’, 16/22 Semibold.
- 2행은 `엄마 · 방금`처럼 `{관계 이름} · {상대 시간}`, 12/18. 해당 아기에 대한 실제 관계값을 우선하며 계정 핸들을 기본 표기로 쓰지 않는다. 관계를 모르는 경우 확인된 표시 이름을 사용한다. 중복 관계는 `엄마 · {표시 이름}`처럼 구별하고 실제 작성자 ID는 그대로 유지한다.
- 3행은 공개범위 아이콘 14와 정확한 텍스트 12/18. 배경색 없는 메타 정보로 사진과 구별한다.
- 여러 아기는 기존 baby 태그와 이름을 사용해 줄바꿈한다. 다른 아기의 이름을 활성 아기 이름으로 대체하지 않는다. 해석되지 않는 ID는 노출하지 않고 ‘아기의 순간’으로 표시한다.
- 상대 시간은 `createdAt`의 게시 시각에서 표시용으로 계산하며 오래된 글은 로케일 날짜로 표시한다. 접근성 설명에는 정확한 날짜·시간도 제공한다. 날짜는 게시일이다. 촬영일, 당시 생후 일수, 성장 마일스톤을 추정하지 않는다. 친구 컨텍스트에는 생일이 없으므로 생후 일수를 표시하지 않는다.
- 작성자 이미지가 없거나 읽기에 실패하면 인물 아이콘으로 돌아간다. 모르는 작성자를 곧바로 ‘탈퇴한 사용자’라고 단정하지 않는다.
- 기존 수정·삭제 권한이 있는 게시물에는 헤더 우측 48×48 더보기 버튼을 둔다. 여기서 ‘추억 수정’으로 바로 들어가고, 삭제는 기존 확인 절차를 유지한다. 댓글 시트에 관리 메뉴를 섞지 않는다.

### 4.5 사진과 비율

사진은 좌우 16을 제외한 폭 `W = 화면 폭 − 32`를 사용한다. 기본 390 화면에서는 W=358이다. 반경은 `radius.md`의 12, 배경은 `colors.cardHi`다.

| 커버 데이터 | 표시 규칙 | 390 화면 예시 |
| --- | --- | --- |
| 유효한 width/height가 있고 비율이 0.8–1.5 | 원본 비율 유지, 프레임을 같은 비율로 설정 | 1:1 → 358×358, 4:3 → 358×268.5 |
| 세로로 긴 사진, 비율 <0.8 | 프레임 4:5, contain으로 전체 사진 보존 | 프레임 358×447.5, 남는 좌우에 중립 배경 |
| 가로로 긴 사진, 비율 >1.5 | 프레임 3:2, contain으로 전체 사진 보존 | 프레임 358×238.7, 남는 위아래에 중립 배경 |
| 비율 정보 없음·잘못된 값·낙관적 카드 | 4:3 예약 공간, contain 사용 | 358×268.5 |

- 배치 높이는 기존 `coverMedia.width/height`로 결정한다. 서버에 크롭·초점 좌표·새 비율 필드를 저장하지 않는다.
- 목록에 머무는 동안 이미지 로드만으로 레이아웃 높이가 갑자기 변하지 않게 한다. 긴 사진의 여백을 강제 크롭으로 없애지 않는다.
- 사진 한 번 탭은 페이지 이동 없이 해당 카드에 머무른다. 두 번 탭은 그 자리에서 좋아요를 추가한다. 이미 좋아요 상태이면 취소하지 않으며, 취소는 하트 버튼으로 한다. 세로 스크롤을 두 번 탭으로 오인하지 않도록 제스처를 구분한다.
- 사진 확대는 별도의 48×48 `크게 보기` 버튼으로 연다. 여러 장이면 `사진 N장 보기` 버튼으로 같은 전체 화면 미디어 뷰어에 진입한다. 기존 `MemoryMediaViewer`의 확대·넘김 기능을 재사용하고 일반 글 상세 화면을 사이에 쌓지 않는다. 닫으면 같은 카드·스크롤 위치로 돌아온다.
- 피드에는 커버만 있으므로 슬라이드 가능한 것처럼 페이지 점이나 ‘1/N’을 표시하지 않는다. `mediaCount > 1`이면 ‘사진 N장 보기’ 버튼을 오른쪽 위에 표시한다. 별도 확대 버튼과 공간을 중복 점유하지 않게 하나의 미디어 보기 진입으로 통합한다.
- 피드마다 전체 미디어를 추가 조회하는 캐러셀을 이번 범위에 넣지 않는다.
- 커버가 없을 때는 ‘사진을 불러올 수 없어요’ 상태와 별도 미디어 보기·재시도 진입을 제공한다. 사진 영역 한 번 탭으로 다른 페이지를 열지 않는다. 아기 이미지를 임의로 만들어 채우지 않는다.
- 기존 사진 업로드 최대 5장과 업로드 상태·재시도 경로를 유지한다. 타입에 video가 있다는 이유로 영상 업로드·자동 재생을 제안하지 않는다.

### 4.6 반응, 이야기, 함께한 사람

**사진 → 반응 행 → 이야기 → 함께한 사람** 순서로 구성한다. 헤더에서 대상과 작성자를 이미 알려주므로 사진 아래는 감상과 대화에 집중한다.

| 요소 | 표현 | 동작과 상태 |
| --- | --- | --- |
| 좋아요 | 24 하트 + ‘좋아요 N’ 14/20 | 기존 heart 반응 토글. 활성은 채움+색상. 진행 중 중복 입력 방지, 실패 시 실제 상태로 복구 |
| 한마디 | 22–24 말풍선 + ‘한마디 N’ | 해당 카드 위로 한마디 시트 열기. 페이지 이동 없음. 뒤 사진은 보이되 어두워지고, 닫으면 피드는 그대로 |
| 저장 | 우측 24 북마크 | 가족 피드에서만 기존 저장 토글. ‘나중에 다시 보기’ 의미이며 성장책에 추가·인쇄·외부 다운로드가 아님 |
| 이야기 | 16/24 Regular, 기본 3줄 | 실제 줄 넘침일 때 ‘더 보기’, 펼친 상태에서 ‘접기’. 문자 수만으로 줄 넘침을 판단하지 않음 |
| 함께한 사람 | ‘함께한 사람 · 이름 · 이름’, 12–14 | 이미 받은 태그와 확인 가능한 이름만 사용. 길면 2줄 요약 후 같은 카드 안에서 펼쳐 전체 확인 |

- 각 반응 버튼 최소 48×48, 버튼 사이 8. 사진 아래 반응 행은 최소 48h, 위 간격 4, 이야기까지 8.
- 반응 수는 API의 실제 집계값이다. 좋아요한 가족의 실명 목록이나 겹친 얼굴을 새로 만들어 표시하지 않는다.
- 이름 태그는 인물 프로필 링크처럼 밑줄 처리하지 않는다. 지원되지 않는 프로필 목적지를 추가하지 않는다.
- 공유·DM·리포스트 아이콘을 넣지 않는다. 태그는 아래 작성 흐름에서 다룬다.
- 카드 하단에서 구분선까지 24, 구분선 다음 헤더까지 24. 피드 표면에는 그림자를 사용하지 않는다.


### 4.7 피드 위 ‘한마디’ 시트

한마디는 해당 순간에 짧게 말하는 공간이다. 기존 `MemoryDetailScreen` 안에 있는 댓글 시트를 피드에서 직접 열도록 재구성한다. 댓글 데이터·작성·삭제·가족 스티커 기능을 재사용하며 새 대화 기능을 만들지 않는다.

```text
┌──────────────────────────────────┐
│ 해당 피드 카드의 사진 일부        │
│ 그대로 남아 있고 살짝 어두워짐    │
├──────────────────────────────────┤
│              ━━━━                │
│              한마디          닫기 │
│                                  │
│ ○ 엄마 · 방금                    │
│   {짧은 한마디}                   │
│                                  │
│ ○ 할머니 · 5분 전                 │
│   {기존 가족 스티커}              │
│                                  │
│       목록만 세로 스크롤           │
├──────────────────────────────────┤
│ 스티커  한마디 남기기…       보내기│
│ 하단 safe area / 키보드 위         │
└──────────────────────────────────┘
```

도식의 관계와 시간은 표시 형식 예시다. 실제 관계와 댓글 작성 시각에서 값을 가져온다.

- **구조:** 손잡이 → 가운데 제목 **한마디** → 목록 → 하단 고정 입력창. 게시물 요약·큰 사진·프로필 소개·별도 통계 섹션을 시트 안에 반복하지 않는다. 제목에 댓글 수를 붙이지 않고 수는 피드에서 표시한다.
- **크기:** 기본 높이는 사용 가능한 화면의 약 65%, 상단 반경 22. 손잡이 36×4, 위아래 8, 제목 20/28. 시트 위에 현재 사진 일부가 보이게 한다. 키보드·큰 글자·작은 화면에서는 목록과 입력 사용성을 우선해 높이를 늘린다.
- **배경:** 피드를 그대로 마운트한 채 약 30% 검정 딤을 덮는다. 사진의 형태가 남도록 강한 블러·불투명 배경을 사용하지 않는다. 시트가 열린 동안 배경의 스크롤·터치·접근성 포커스는 잠근다.
- **열기:** 피드의 말풍선·‘한마디 N’을 누르면 해당 게시물 ID로 시트를 연다. 키보드는 자동으로 올리지 않는다. 사진이 화면 밖에 있는 경우 필요한 최소 거리만 맞춰 사진 일부를 남기고, 닫을 때 원래 피드 위치로 복귀한다.
- **닫기:** 손잡이/헤더를 아래로 드래그하거나, 목록이 맨 위일 때 아래로 내려 닫는다. 목록 중간의 아래 스크롤은 시트 닫기로 처리하지 않는다. 배경 탭, 닫기 버튼, 시스템 뒤로가기도 제공한다. 키보드가 열렸을 때 시스템 뒤로가기는 먼저 키보드를 닫는다.
- **목록:** 작성자 아바타 32, 관계·상대시간 12/18, 본문 16/24, 행 사이 16. 목록만 스크롤되고 손잡이·제목·입력은 고정된다. 답글 스레드, GIF, 불꽃 이모지 바, 새 반응 종류를 추가하지 않는다.
- **빈 목록:** ‘첫 한마디를 남겨보세요’ 한 줄만 표시하고 입력창은 그대로 둔다. 큰 일러스트나 부가 추천 영역으로 시트를 채우지 않는다.
- **작성자:** `ddodddori` 같은 계정 핸들보다 **엄마 · 방금**, **할머니 · 5분 전**을 우선한다. 해당 게시물 아기와의 확인된 관계를 사용하며 친구 피드에 내 활성 아기의 관계를 대입하지 않는다. 관계가 없으면 확인된 표시 이름, 그것도 없으면 ‘작성자’를 사용한다. 같은 관계가 여럿이면 표시 이름을 보조로 붙인다.
- **입력:** 높이 최소 48, 1–3줄까지 늘어나고 그 이상은 입력 내부 스크롤. placeholder는 ‘한마디 남기기…’. 비어 있거나 전송 중이면 보내기 비활성. 키보드가 열리면 입력창은 키보드 바로 위에 고정한다.
- **스티커:** 입력창 옆 작은 버튼으로 현재 허용된 가족 스티커만 펼친다. 선택 영역은 같은 시트 안에서 입력창 위에 잠시 열고, 선택하면 접는다. 스티커가 없으면 큰 빈 스티커 패널·만들기 유도 영역을 넣지 않는다. 친구 전용은 현재처럼 텍스트 작성만 제공한다. 짧은 반응은 일반 텍스트로 남기며 새 저장 타입을 만들지 않는다.
- **전송:** 기존 댓글·스티커 API를 사용한다. 성공 시 목록과 해당 피드 카드의 댓글 수를 같은 게시물 ID 기준으로 갱신하며, 시트를 자동 닫거나 피드를 다시 맨 위부터 로딩하지 않는다. 중복 전송을 방지한다. 실패 시 입력을 유지하고 입력창 위에 재시도를 제공한다.
- **초안:** 아래로 닫기는 바로 닫히되 미전송 텍스트는 현재 피드 세션의 해당 게시물에만 메모리로 보관한다. 다시 열면 복원한다. 앱 재시작 복원·디스크 저장·서버 초안은 추가하지 않는다. 게시물별 초안이 섞이지 않게 한다.
- **권한·예외:** 기존 댓글 삭제 권한과 확인 절차를 유지한다. 목록 로딩 실패는 시트 안에서 재시도하고 피드는 그대로 둔다. 게시물 접근이 철회되면 내용을 숨기고 작성 컨트롤을 비활성화한다.

### 4.8 전체 화면과 외부 진입 규칙

| 사용자 행동 | 도착 화면 | 닫기·복귀 |
| --- | --- | --- |
| 피드 사진 한 번 탭 | 현재 카드, 이동 없음 | 그대로 |
| 피드 사진 두 번 탭 | 현재 카드에서 좋아요 추가 | 그대로. 이미 좋아요면 유지 |
| 하트 버튼 | 현재 카드에서 좋아요/취소 | 그대로 |
| 한마디 아이콘·문구 | 현재 피드 위 한마디 시트 | 아래로 닫으면 같은 카드·피드 위치 |
| 크게 보기·사진 N장 보기 | 미디어 전용 전체 화면에서 확대·넘김 | 기존 피드 위치. 글 상세 화면을 중간에 넣지 않음 |
| 추억 수정 | 권한 있는 사용자만 기존 수정 폼을 전용 전체 화면/모달로 표시 | 저장·취소 후 같은 카드. 기존 저장 계약·폐기 확인 유지 |
| 한눈에 ‘우리 순간 확인하기’ | 기존 우리 순간 피드의 연결된 카드 | 필요한 경우에만 한마디 시트. 별도 상세 페이지 없음 |
| 해당 순간 알림 | 권한에 맞는 피드의 해당 카드 | 댓글 관련 알림이면 한마디 시트, 일반 순간 알림이면 카드만 표시 |

한눈에·알림은 피드 밖에서 들어오는 진입점이다. 해당 순간을 보기 위해 피드 화면으로 전환할 수 있지만 글 상세 페이지를 하나 더 쌓지는 않는다. 전체 화면 읽기 목적지는 미디어 보기이고, 편집 목적지는 수정 폼이다.

연결된 순간을 찾는 흐름:

1. 기존 게시물 ID와 사용자의 가족/친구 접근 맥락을 내부 UI 요청으로 전달한다. 알림 payload나 API 계약은 바꾸지 않는다. UI용 대상 ID·시트 열기 의도 전달은 작은 화면 연결 변경으로 허용한다.
2. 기존 피드 인스턴스를 재사용한다. 현재 카드 목록에 대상이 있으면 해당 카드로 스크롤한다. 카드 높이가 확정된 후 위치를 맞추고 대상 요청은 한 번만 소비한다.
3. 현재 필터가 대상을 숨기면 UI에서 해당 보기 조건을 잠시 해제하고 변경 사실을 짧게 알린다. 평소의 필터·스크롤 상태는 세션 메모리에 두어 복귀 시 복원한다. 권한으로 볼 수 없는 글은 필터 해제로 노출하지 않는다.
4. 대상이 아직 로드되지 않았다면 기존 `getBundleById` 등 허용된 조회로 대상의 접근 가능 여부와 내용을 확인한다. 필요 시 같은 피드 안에 대상 카드를 임시 포함하고 ID로 중복 제거한다. 주변 글은 기존 페이지네이션을 재사용하며 새 서버 검색 API나 별도 상세 화면으로 우회하지 않는다.
5. 대상 카드의 사진이 보이는 위치에 맞추고 짧고 옅은 강조로 도착을 알려준다. 댓글 진입 의도가 있으면 위치가 잡힌 뒤 한마디 시트를 연다. 댓글 순번·ID가 없으면 특정 댓글까지 찾았다고 표시하지 않는다.
6. 시트 닫기는 도착한 피드 위치를 유지한다. 출발 화면으로 돌아가면 출발 화면의 상태를 보존하고, 같은 알림 재탭·뒤로가기에서 피드나 상세 페이지가 중복 적재되지 않게 한다.
7. ID가 없으면 기본 피드로 진입한다. 삭제·권한 없음이면 ‘이 순간을 볼 수 없어요’, 조회 실패이면 재시도를 피드 안에 표시한다. 대상 조회가 늦어지는 중 사용자가 다른 화면으로 이동하면 뒤늦게 시트를 열지 않는다.

피드 위치·선택 게시물·미전송 입력·시트 열림은 일시적인 UI 상태다. 새 영속 저장을 만들지 않는다. 가족과 친구 피드 모두 시트 열기/닫기, 좋아요, 댓글 전송 때문에 목록을 비우거나 처음부터 재마운트하지 않는 것이 필수 조건이다.

## 5. 가족·친구 태그와 공개 범위

### 5.1 기존 기능에 맞춘 태그

‘누구의 순간’, ‘함께한 사람’, ‘볼 수 있는 사람’을 서로 다른 의미의 섹션으로 배치한다.

| 기존 데이터·동작 | 제안 UI | 이번 범위 |
| --- | --- | --- |
| `baby` / `babyId` | ‘이 순간의 아기’, 현재 허용된 아기 목록에서 선택 | 기존 선택과 draft 유지 |
| `family_member` / `taggedUserId` | ‘가족 태그’, 활성 구성원 이름·관계를 읽기 쉬운 선택 행으로 표시 | 기존 구성원 목록과 태그 콜백 재사용 |
| `manual_guest` / `manualLabel` | ‘친구·함께한 사람 이름’, 계정 연결 없는 이름 기록 | 편집 모달에 이미 있는 입력을 정돈. 작성 모달에도 같은 입력을 제공하는 작은 UI 확장 제안 |
| `friend_baby` / `taggedBabyId` | 신규 선택 UI 없음 | 읽기 타입에는 있으나 `MemoryTagDraft`와 현재 작성 UI에 없음. 친구 아기 검색·선택·승인 기능을 만들지 않음 |

친구 이름 입력은 현재 `manual_guest` draft를 사용한다. 새 태그 타입이나 API 필드를 만들지 않는다. 안내문은 **‘이름만 기록돼요. 계정 연결이나 열람 권한은 추가되지 않아요.’**로 한다. 이름을 적은 친구에게 알림·초대가 전달된다고 표시하지 않는다.

따라서 이번 설계에서 친구 태그는 이름 기록까지다. 친구 계정 검색, 실제 계정 멘션, 상대 승인, 알림이 필요한 태그는 후속 별도 기능이며 이번 구현 범위에 포함하지 않는다.

피드의 태그 표현은 기존 `status`를 존중한다. 승인된 태그를 기본 표시하고, 대기·거절 태그를 승인된 관계처럼 표시하지 않는다. 대기 상태를 작성자에게 보여줄 때는 ‘확인 대기’를 붙이며 신규 승인 동작은 제공하지 않는다.

### 5.2 공개 범위의 정확한 설명

현재 작성 선택기는 가족 공개·친구 공개·나만 보기의 3개다. 선택지와 초기값은 유지하고, 기존 제한 공개 게시물의 표시를 정확하게 만든다.

| 저장된 값 | 표시 이름 | 설명 |
| --- | --- | --- |
| `family_circle` | 가족 공개 | 함께 기록하는 가족이 볼 수 있어요 |
| `friend_circle` | 가족·친구 공개 | 함께 기록하는 가족과 연결된 친구가 볼 수 있어요 |
| `only_me` | 나만 보기 | 작성자만 볼 수 있어요 |
| `tagged_family` | 태그된 가족 | 작성자와 승인된 태그의 가족이 볼 수 있어요 |
| `selected_people` | 선택한 사람 | 작성자와 선택한 사람이 볼 수 있어요 |

`friend_circle`은 로컬 마이그레이션의 열람 함수상 가족과 연결된 친구를 모두 포함한다. 단순히 ‘친구만’이라고 안내하지 않는다. 이 확인은 로컬 코드 기준이며 운영 DB의 적용 상태를 검증한 것은 아니다.

- 제한 공개값이 있는 기존 게시물을 편집할 때 해당 현재값을 별도 행으로 보여주고 유지한다. 일반 가족 공개로 자동 변환하지 않는다.
- 일반 가족·친구 공개에서 태그를 추가하는 것과 공개 대상을 변경하는 것은 별개다. `tagged_family`에서는 승인된 가족 태그가 열람 대상에 영향을 주므로 해당 사실을 명시한다.
- 피드 필터는 보기 조건일 뿐 권한 제어가 아니다. 비공개 표시나 자물쇠 아이콘을 보안 구현으로 설명하지 않는다.
- 모든 사람에게 보이는 탐색, 공개 링크 공유, 팔로워 수, 친구 수 순위는 제공하지 않는다.

### 5.3 작성·편집 흐름

1. ‘추억 올리기’ → 기존 업로드 모달.
2. 사진 선택·미리보기 → 기존 최대 5장과 전송 상태 표시.
3. 짧은 이야기 입력.
4. 이 순간의 아기 또는 가족 순간 선택.
5. 함께한 사람: 가족 선택, 선택적인 친구 이름 기록.
6. 공개 범위 확인 → 현재 값에 대응하는 설명을 게시 버튼 근처에 반복 표시.
7. 기존 제출 핸들러로 게시 → 현재 성공·실패·재시도 흐름 유지.

작성 중 닫기는 기존 내용 폐기 확인을 유지한다. 임시저장 버튼, 자동 초안 복원, 새 저장소는 추가하지 않는다. ‘올리는 중’과 ‘게시 완료’를 구별하고 실패한 게시물을 완료 상태로 꾸미지 않는다.

## 6. 친구 전용 화면

- 현재 `friendOnly` 진입과 친구 열람 권한 맥락을 유지한다. 친구 피드도 사진 한 번 탭은 머무름, 두 번 탭은 좋아요, 한마디는 시트로 통일한다. `source: "friend"`의 권한 구분은 시트·미디어 보기에도 전달하되 글 상세 페이지를 거치지 않는다.
- 제목은 ‘친구의 순간’, 설명은 ‘연결된 가족이 나눠 준 아기의 순간’으로 제안한다.
- 같은 게시물 헤더·사진·본문 규격을 사용한다. 아기 이름은 `FriendMemoryContext.babyName`, 작성자는 기존 visible profile에서 가져온다.
- 친구 측에는 가족 관리·작성·설정·저장 컨트롤을 새로 넣지 않는다. 알림 진입·좋아요·댓글의 기능은 유지하며 댓글 진입만 피드 위 한마디 시트로 옮긴다. 친구에게 없던 가족 스티커 작성 권한은 추가하지 않는다.
- 아바타 가로 목록과 새로운 친구별 필터는 이번 필수 범위에서 제외한다. 기존 컨텍스트 조회와 정렬·페이지네이션을 바꾸지 않는다.
- 친구 전용은 현재처럼 하단 탭 바를 표시하지 않는다. 일반 가족 계정의 내비게이션을 복제하지 않는다.
- 연결된 친구 맥락이 없는 상태와 연결은 있지만 글이 없는 상태를 구별한다. 가능한 기존 알림 진입으로 초대 상태를 확인하게 하되, 새 초대 버튼이나 목적지를 가정하지 않는다.

Android는 현재 테마의 플랫폼 시맨틱 색 매핑을 유지한다. 위 hex를 Android 전역에 강제하거나 Community 작업 때문에 전역 테마 값을 바꾸지 않는다.

### 7.1 타이포그래피

| 역할 | 크기 / 줄높이 / 굵기 |
| --- | --- |
| 화면 제목 | 24 / 30 / 700 |
| 시트 제목 | 20 / 28 / 600 |
| 아기·게시물 정체성 | 16 / 22 / 600 |
| 본문·댓글 입력 | 16 / 24 / 400 |
| 버튼·작성자 보조 정보 | 14 / 20 / 500–600 |
| 날짜·공개범위·필터 라벨 | 12 / 18 / 400–500 |

기존 시스템 폰트를 유지한다. 새 영문 전용 세리프, Instagram 워드마크, 브랜드 아이콘·참조 사진을 도입하지 않는다. 한국어·일본어·중국어 본문에 음수 자간을 일괄 적용하지 않는다.

### 7.2 하단 내비게이션

이번 설계의 기본안은 기존 `MainTabs` 하단 바를 그대로 재사용하는 것이다. Figma의 5개 아이콘 바는 비교 근거일 뿐 교체 사양이 아니다.

- 기록 / 일기 / 음성 액션 / 한눈에 / 우리 순간의 순서와 라우트 유지.
- 중앙 마이크는 계속 음성 육아 기록이며 게시물 작성으로 바꾸지 않는다.
- 기존 상단 모서리 18과 그림자·마이크 구조는 전역 변경이므로 이번 필수 구현에서 제외한다.
- 사진 마지막 부분과 반응 버튼이 하단 바에 가리지 않도록 실제 바·safe area 점유를 확인한다. 하단 인셋을 두 번 더하지 않는다.
- 내비게이션 라벨, 선택 상태, 읽기 전용 음성 동작을 유지한다.

## 8. 상태·접근성·반응형 설계

| 상황 | UI 설계 |
| --- | --- |
| 최초 로딩 | 게시물 헤더·사진 자리의 정적인 스켈레톤, ‘순간을 불러오는 중’. 필터와 뒤로 갈 수 있는 경로 유지 |
| 새로고침 | 기존 refresh 상태 사용. 불필요한 장식 애니메이션 없이 진행 상태 표시 |
| 첫 게시물 없음 | ‘첫 순간을 남겨보세요’. 작성 가능한 사용자에게만 기존 작성 버튼 |
| 필터 결과 없음 | 선택한 조건 설명과 ‘필터 초기화’. 전체 피드에 글이 없다고 단정하지 않음 |
| 로딩·페이지 실패 | 실제 오류 상태에 맞는 재시도. 현재 두 목록은 error일 때 data를 비우므로 캐시 유지가 이미 된다고 주장하지 않음 |
| 반응·저장 처리 중 | 해당 액션만 busy/disabled 표시. 완료 전 숫자 증가를 중복 적용하지 않음 |
| 반응·저장 실패 | 기존 API 실패에 맞게 상태 복구·문구 표시. 친구 피드도 전체 목록을 비우거나 맨 위로 되돌리지 않고 해당 카드에서 피드 위치를 유지 |
| 사진 업로드 실패 | 게시 완료와 구별되는 상태 텍스트 + 현재 재시도 동작. 사진 속 얼굴을 덮는 큰 경고 패널은 피함 |
| 접근 불가·삭제된 게시물 | 피드 또는 열린 시트 안에서 접근 불가 안내. 시트 닫기·출발 화면 복귀 제공. 다른 아기의 정보를 대신 표시하지 않음 |
| 한마디 목록 로딩·실패 | 시트 목록 영역에만 로딩·재시도 표시. 뒤의 피드 카드는 유지 |
| 한마디 전송 실패 | 입력 내용 유지, 입력창 가까이에 오류·재시도. 성공으로 집계하지 않음 |
| pressed / selected / disabled | 눌림은 명도·불투명도, 선택은 아이콘 채움+텍스트, 비활성은 설명·상태와 함께 전달 |
| 게시·댓글 성공 | 기존 결과 상태를 짧게 읽어 줌. 새 알림이나 축하 애니메이션을 만들지 않음 |

접근성 기준:

- 모바일 액션은 공통 최소 48×48로 설계한다. 작은 원형 이미지·아이콘의 시각 크기와 터치 크기를 분리한다.
- 일반 텍스트 대비 목표 4.5:1, 큰 글자와 필수 컨트롤 3:1. 옅은 border는 장식이며 선택 여부를 그 색만으로 전달하지 않는다.
- 큰 글자에서 제목·메타는 줄바꿈하고 반응 행도 높이를 늘린다. 본문 자동 축소로 해결하지 않는다. 기존 chrome 글자 확대 제한은 실제 기기에서 별도 검증한다.
- 읽기 순서는 아기/작성자 → 날짜/공개범위 → 사진 설명·크게 보기 → 반응·한마디 → 본문 → 함께한 사람이다.
- 아이콘 버튼에 의미 있는 이름·선택·비활성 상태를 제공한다. 아바타는 독립 동작이 없으면 불필요한 포커스를 만들지 않는다.
- 시트를 열면 내부로 포커스를 옮기고 닫으면 호출 버튼으로 복귀한다. 키보드·뒤로가기·스크린리더 닫기 동작을 제공한다.
- 모션 감소 설정에서는 스켈레톤 움직임과 확대 누름 효과를 생략한다. 확대·좋아요는 제스처 외에도 기존 버튼 경로가 있다.

반응형·국제화 기준:

- 320 / 375 / 390 / 430 폭을 확인한다. 큰 화면에서는 피드 최대 폭 600으로 중앙 정렬하고, 이번에는 다열 피드를 추가하지 않는다.
- 텍스트 확대 시 원형 필터 라벨과 공개범위는 2줄 이상을 허용한다. 화면 높이를 고정하지 않는다.
- 현재 번역 언어인 한국어·영어·일본어·스페인어·중국어에서 긴 이름, 날짜, 버튼 문구를 확인한다.
- 입력 폼은 키보드가 열려도 현재 필드와 게시 상태를 읽을 수 있게 한다. 웹 검증 시 Tab 이동, Enter/Space, Escape로 시트 닫기를 확인한다.
- 상태바 44와 하단 34는 Figma 기기의 치수일 뿐이다. 실제 시스템 인셋으로 처리한다.

## 10. 검증과 수용 기준

이번에 수행한 검증:

- Figma 지정 노드의 스크린샷을 시각 확인하고 메타데이터와 대조했다.
- 현재 두 피드, 상세, 업로드·편집·태그·공개범위·필터 컴포넌트, 내비게이션, 테마와 타입을 읽었다.
- 공개범위 문구를 확인하기 위해 관련 로컬 SQL의 열람 조건을 읽었다. DB 실행이나 데이터 접근·변경은 하지 않았다.
- 변경 산출물은 이 문서 한 개다. 앱 빌드·테스트·기기 조작을 하지 않았다.

확인하지 못한 사항:

- 실행 중인 Darin의 실제 스크린샷, 실제 사용자 데이터, 기기별 렌더링·성능·대비·스크린리더 동작.
- 운영 DB가 로컬 마이그레이션과 일치하는지 여부.
- 프레임에 없는 홈 피드 반응 행과 프로토타입 동작.
- 최신 플랫폼 문서 검증. 이 문서는 버전별 API 구현·마이그레이션 지침을 제시하지 않는다.

후속 구현 수용 기준:

1. 5초 안에 ‘우리 아기/친구 아기의 순간’, 작성자, 실제 공개 범위, 사진 확대·좋아요·한마디 진입을 이해할 수 있다.
2. 320 폭과 큰 글자에서 가로 넘침·잘린 이름·중첩 터치 영역이 없다. iOS·Android safe area와 키보드가 주요 버튼을 가리지 않는다.
3. 세로·정사각·가로·크기 정보 없는 사진과 1장/복수 사진을 확인하고, 피드 커버의 전체 사진을 볼 수 있다.
4. 가족 순간·여러 아기·이름/사진 없음·아주 긴 본문·수동 친구 이름이 정확하게 표현된다.
5. 일반 사용자·viewer·친구 전용 진입에서 현재 허용된 동작만 보인다. 친구 전용에 작성·저장·일반 하단 바가 생기지 않는다.
6. 좋아요·저장·댓글·업로드 성공/실패 및 재시도·중복 누름을 기존 동작과 비교한다. 새 저장 방식이 추가되지 않는다.
7. 다섯 공개범위 값이 서로 오해되지 않게 표시되고 기존 값은 편집 시 자동 변경되지 않는다.
8. 시트와 피드 위치 찾기에 기존 조회 API를 재사용한다. API 요청 계약, 권한 판정, 저장 모델에 변화가 없고 diff는 UI·화면 연결 범위에 한정된다.
9. Instagram 워드마크·사진·브랜드 자산·스토리·팔로워 지표가 포함되지 않는다.
10. 최종 화면은 사진, 따뜻한 중립색, 정확한 여백으로 프리미엄 베이비북의 성격을 전달한다.

11. 사진 한 번 탭은 이동하지 않고 두 번 탭은 좋아요를 추가한다. 이미 좋아요한 사진의 두 번 탭으로 좋아요가 취소되지 않는다.
12. 한마디 시트가 열려도 뒤 사진이 남아 있고 딤이 적용된다. 목록과 드래그 닫기가 충돌하지 않으며 입력창은 키보드 위에 고정된다.
13. 시트 닫기·재열기·댓글 전송·좋아요 전후에 같은 피드 카드와 스크롤이 유지된다. 실패 시 입력 내용과 정확한 반응 수를 보존한다.
14. 한눈에·알림은 대상 피드 카드로 진입하고 필요할 때만 시트를 연다. 미로딩·필터로 숨겨진 대상·삭제·권한 없음·느린 응답·반복 진입에서 상세 페이지가 추가되지 않는다.
15. 전체 화면은 수정·미디어 보기로 한정된다. 시트에는 손잡이·가운데 ‘한마디’·목록·고정 입력을 두고 GIF·불꽃 반응 바는 없다. 관계가 확인된 작성자는 ‘엄마 · 방금’ 형식으로 표시된다.
